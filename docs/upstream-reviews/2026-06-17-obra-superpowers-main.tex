\subsection{Executive Summary}

Upstream has moved from the local fork's v4.3.1 lineage to v6.0.2. The delta is not a narrow patch series. It is a broad product and methodology release train that adds new agent harnesses, a visual brainstorming companion, substantial subagent-driven-development changes, new packaging and marketplace tooling, cross-platform hook fixes, and a new eval/testing strategy.


The local project is not merely stale; it has fork-specific functionality that upstream does not contain. The most important local-only work is the \texttt{br} / beads integration, Micah-owned package metadata, local Codex CLI packaging, local documentation/review artifacts, and four local skills not present upstream: \texttt{characterization-\penalty0 testing}, \texttt{context-\penalty0 7}, \texttt{knowledge-\penalty0 lineages}, and \texttt{strangler-\penalty0 fig-\penalty0 pattern}.


If this project were updated by a direct merge, it would import many real fixes and new capabilities, but it would also delete or overwrite local fork behavior. The right approach is selective porting or an intentional rebase with a preservation checklist.

\begin{itemize}

\subsubsection{Visual Companion Security Model}

Upstream v6 hardens the visual companion:


\begin{itemize}
\setlength{\itemsep}{0pt}
\setlength{\parskip}{0pt}
  \item Per-session key required for every HTTP and WebSocket request.
  \item Key carried in the URL and stored in a tab-scoped cookie.
  \item File server refuses symlinks, dotfiles, resource-fork files, path traversal, and files outside the content sandbox.
  \item No-store and deny-framing headers are sent.
  \item Key-bearing files are owner-only.
  \item \texttt{stop-\penalty0 server.\penalty0 sh} checks process ownership before signaling.
  \item Windows lifecycle handling avoids unsafe POSIX ownership assumptions.
\end{itemize}

These are real security fixes. If the local fork ever imports the visual companion, these hardening changes should be imported with it.
